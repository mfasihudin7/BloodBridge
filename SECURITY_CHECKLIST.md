# Raabta & BloodBridge Security & Privacy Checklist

## 1. Credentials & Secrets Management
- [x] **No hardcoded secrets**: Verified that no `SUPABASE_SERVICE_ROLE_KEY`, `CRON_SECRET`, or private tokens exist in browser bundles or git tracking.
- [x] **Environment Separation**: Client code strictly consumes `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
- [x] **Service Role Isolation**: Server-only operations (admin cleanup, elevated OCR verification, expansion daemon) exclusively run within server route handlers (`src/app/api/...`).

---

## 2. Row Level Security (RLS) & Access Control
- [x] **Profile Protection**: Users can only modify their own profile rows (`auth.uid() = id`).
- [x] **Location Privacy**: PostGIS donor coordinates are strictly stripped from public endpoints. Only approximate distance calculations occur in server matching functions.
- [x] **Contact Concealment**: Requester and donor phone numbers remain invisible until explicit commitment acceptance (`accept_request` RPC).
- [x] **CNIC Storage Isolation**: CNIC verification photos are stored in a private Supabase Storage bucket with zero public access. Viewing documents requires short-lived (5-minute) authenticated signed URLs generated by admins.

---

## 3. Data Integrity & Safety Controls
- [x] **No Fake Data or Mocks**: All matching timestamps (`next_expansion_at`), invited counts, and donation records are authoritative and derived from real PostgreSQL tables.
- [x] **Availability Safeguard**: Toggling donor availability to `OFF` instantly disengages the donor from all pending expansion scheduler queries.
- [x] **Mutual Confirmation**: Donation counts increment solely after recipient reporting followed by explicit donor confirmation or admin dispute resolution.
- [x] **Account Deletion Protocol**: `DELETE /api/account` enables voluntary right-to-be-forgotten removal of user records.
